# V9: диагностический прогон перед окончательными исправлениями

Обновлено 8 ноября 2026 года. Это сохранённый результат V9. Актуальная сводка итоговой конфигурации — в DEV_REVIEW_SUMMARY.md.

12 DEV-чатов: по четыре RU/KZ/EN, 96 предварительных решений ассистента, записанных до просмотра V4. Это калибровочная выборка, не независимый тест и не официальный Ground Truth. Исходные транскрипты и подробная локальная разметка в Git не добавлены.

Новая версия: 10/12 принятых результатов, 2 ошибок.
Время на этой машине для 10 принятых оценок: медиана 230.2 с, диапазон 169.2–407.2 с (включая повторные запросы). Время неуспешных случаев в эту медиану не входит.
На общих 10 успешных парах MAE итога: V4 3.598 → новая версия 5.531. Деноминатор и ошибки указаны отдельно; пропуски не приравниваются к совпадениям.
Точные значения на тех же парах: 57/80 → 70/80. Эта метрика не проверяет качество объяснений.

Обнаруженные повторяющиеся проблемы: приписывание бота/клиента оператору, N/A и пропущенное действие, прощание без итога/помощи, неподтверждённая идентификация перед раскрытием статуса счёта, причина, не соответствующая процитированной реплике.

Изменения выбраны по этому разбору: ограниченный режим рассуждения Qwen, проверки доказательств и повторный запрос только по невалидным критериям с сохранением остальных решений. Проверки не вставляют ответы из разметки и не содержат исключений по ID диалогов.

Это ретроспективное сравнение с историческим V4, у которого нет полного снимка настроек. Менялись несколько компонентов; это не эксперимент с одним изменяемым фактором. Новая версия всё ещё выдаёт шаблонные и противоречивые объяснения и ошибается в применимости N/A. Подробные замечания по каждой принятой оценке сохранены в локальном отчёте.

Программные проверки: 87 тестов unittest, синтаксис JavaScript. Они проверяют расчёт, сохранение, импорт/экспорт, защиту ревизий и контракт модели, а не её точность.

В браузере проверены новый диалог → реальная оценка → доказательство → апелляция → решение → пересчёт, восстановление серверной истории без localStorage, изменение чек-листа и сохранение старой версии. Дополнительные проверенные сценарии перечислены в WORKFLOW_UPDATE_RU.md и локальном отчёте.
